# Plan: Compile-time Config Schema Type Safety

## Overview

Every `impl ConfigConstructable` today manually deserializes a specific config struct from
`serde_json::Value`, then separately re-declares the same struct in `config_schema()` via
`schemars::schema_for!(SameStruct)` inside `impl Has*Metadata`. This pairing is enforced
only by convention — a divergence is silent and correct-looking.

The fix: add an associated type `Config` to `ConfigConstructable`. The `MetaOf<T>` bridge
in `define_factory!` then derives `config_schema()` and `default_config()` directly from
`T::Config`, making those methods non-overridable (they are removed from `Has*Metadata`).
The guarantee is structural: the schema always matches the type that `new` deserializes.

This is the Rust equivalent of template metaprogramming — the type parameter `T` already
flows into `register<T>(...)`, and `T::Config` is resolved at monomorphization time.

**Scope:** `src/registry/mod.rs`, all `impl ConfigConstructable` blocks (7 production + 3
test doubles), all `impl Has*Metadata` blocks that override `config_schema` /
`default_config`.

**Non-goals:** No changes to `metadata()`, `ProviderMetadata`, or any factory lookup logic.

- `NoConfig` is defined and exported from `src/registry/mod.rs`
- `NoConfig` derives `JsonSchema + Serialize + Deserialize + Default`

### Sub-task 2 — Remove `config_schema` / `default_config` from `Has*Metadata` and derive them in `MetaOf<T>`

**Intent**

The macro-generated `Has*Metadata` trait currently has defaulted `config_schema()` and
`default_config()` methods that implementations override. Remove them from the trait
entirely and instead implement them inside `MetaOf<T>` by consulting `T::Config` directly.
This makes the schema impossible to override incorrectly.

**Expected Outcomes**

- `Has*Metadata` (generated by `define_factory!`) no longer declares `config_schema()` or
  `default_config()` methods
- `MetaOf<T>`'s impl of the internal `*Metadata_` trait provides `config_schema()` as
  `schemars::schema_for!(T::Config)` and `default_config()` as
  `serde_json::to_value(T::Config::default()).unwrap_or_default()`
- The `where` clause on `impl<T> *Metadata_ for MetaOf<T>` gains
  `T: ConfigConstructable` (already required indirectly, now made explicit so `T::Config`
  resolves)
- The factory's public `config_schema()` and `default_config()` methods remain unchanged
  in signature (they still return `Option<schemars::Schema>` / `Option<serde_json::Value>`)

**Todo List**

1. In `define_factory!` in [`src/registry/mod.rs`](src/registry/mod.rs), delete the
   `config_schema()` and `default_config()` method bodies from `Has*Metadata`
2. In the `impl<T> [<$trait Metadata_>] for MetaOf<T>` block, replace the delegating
   bodies of `config_schema` and `default_config` with direct derivations from `T::Config`:
   - `fn config_schema(&self) -> schemars::Schema { schemars::schema_for!(T::Config) }`
   - `fn default_config(&self) -> serde_json::Value { serde_json::to_value(T::Config::default()).unwrap_or_default() }`
3. Add `T: ConfigConstructable` to the `where` clause on that `impl` block (it is currently
   implied by the supertrait chain but should be explicit now that `T::Config` is used)

**Relevant Context**

- [`src/registry/mod.rs:91-113`](src/registry/mod.rs) — `Has*Metadata` with defaulted methods to remove
- [`src/registry/mod.rs:115-136`](src/registry/mod.rs) — `MetaOf<T>` impl to update
- `schemars::schema_for!(T)` accepts a type parameter, not a value — this works in a
  generic context as long as `T: JsonSchema` is in scope

**Status:** [ ] pending

## Change Summary

```
ConfigConstructable  →  gains: type Config: JsonSchema + Serialize + Default
Has*Metadata         →  loses: config_schema(), default_config() (no longer needed)
MetaOf<T> impl       →  changes: derives config_schema / default_config from T::Config
NoConfig             →  new: unit struct for impls with no real config

Per-impl changes (7 prod + ~3 test):
  impl ConfigConstructable  →  add: type Config = <SpecificStruct>
  impl Has*Metadata         →  remove: config_schema(), default_config() bodies
```

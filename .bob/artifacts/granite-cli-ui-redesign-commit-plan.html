What goes in output.rs

pub trait Output: Send + Sync {
    fn table(&self, title: &str, headers: &[&str], rows: &[Vec<String>]);
    fn detail(&self, title: &str, fields: &[(&str, String)]);
    fn status(&self, label: &str, ok: bool, detail: &str);
    fn info(&self, msg: &str);
    fn warn(&self, msg: &str);
    fn error(&self, msg: &str);
}

// CaptureOutput uses RefCell<Vec> internally because Output methods
// take &self — interior mutability is required for the spy to record calls.
pub struct CaptureOutput {
    pub tables:   RefCell<Vec<(String, Vec<String>, Vec<Vec<String>>)>>,
    pub details:  RefCell<Vec<(String, Vec<(String, String)>)>>,
    pub statuses: RefCell<Vec<(String, bool, String)>>,
    pub infos:    RefCell<Vec<String>>,
    pub warns:    RefCell<Vec<String>>,
    pub errors:   RefCell<Vec<String>>,
}
RefCell is Rust's way of saying "I promise only one thing accesses this at a time, but I need to mutate through a shared reference." It's safe for single-threaded test code. Commands run single-threaded, so this is fine.
✓ 68 → 68 tests (no existing tests affected — purely additive)

What render_once does

// src/utils/ui/tui.rs
pub fn render_once(widget: impl Widget + 'static) -> anyhow::Result<()> {
    crossterm::terminal::enable_raw_mode()?;
    let mut t = Terminal::new(CrosstermBackend::new(std::io::stdout()))?;
    t.draw(|frame| frame.render_widget(widget, frame.area()))?;
    crossterm::terminal::disable_raw_mode()?;
    Ok(())
}

What TerminalOutput::table() now does

fn table(&self, title: &str, headers: &[&str], rows: &[Vec<String>]) {
    let header_row = Row::new(headers.iter().map(|h| Cell::from(*h).bold()));
    let data_rows: Vec<Row> = rows.iter()
        .map(|r| Row::new(r.iter().map(|c| Cell::from(c.as_str()))))
        .collect();
    let widths = /* auto-calculate from content */;
    let table = Table::new(data_rows, widths)
        .header(header_row)
        .block(Block::bordered().title(title));
    render_once(table).unwrap_or_else(|_| { /* fallback to PlainOutput */ });
}
If render_once fails (e.g. stdout is not a tty — piped to a file), fall back to the PlainOutput impl silently. This makes granite-cli model catalog > out.txt still work correctly.

App state

pub enum Section { Models, Providers, Capabilities }
pub enum AppMode { Browse, Detail(String) }

pub struct App {
    ctx: AppContext,
    section: Section,     // which left-nav item is selected
    row: usize,           // which row in the content table is selected
    mode: AppMode,        // Browse = table, Detail(id) = detail pane
}

Key bindings

KeyCode::Char('q') | KeyCode::Esc  → quit
KeyCode::Tab                        → cycle section (Models → Providers → Capabilities)
KeyCode::Up / KeyCode::Char('k')   → row up
KeyCode::Down / KeyCode::Char('j') → row down
KeyCode::Enter                      → AppMode::Detail(selected_id)
KeyCode::Backspace                  → back to Browse

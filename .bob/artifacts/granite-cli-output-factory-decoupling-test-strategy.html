1. Does it need its own factory? Yes — here's why

The previous plan proposed a plain trait + two hardcoded impls. That works for two modes but breaks down the moment you add a third — JSON output for scripts, a Markdown reporter, a CI-friendly no-colour mode, etc. The existing factory pattern already solves exactly this problem for Providers and Models. The Output system should use the same infrastructure.

Without factory (fragile)
// main.rs — grows every time
let out: Box<dyn Output> = match mode {
    Mode::Tui      => Box::new(TuiOutput::new()),
    Mode::Terminal => Box::new(TerminalOutput::new()),
    Mode::Json     => Box::new(JsonOutput::new()),  // added later, requires editing main.rs
    Mode::Markdown => Box::new(MdOutput::new()),    // another edit
};
With factory (open/closed)
// main.rs — never changes
let out = OUTPUT_REGISTRY
    .construct(mode_name, &cfg)?;
// Adding a new format = new file + one
// register() call. main.rs untouched.

The Open/Closed Principle — open for extension, closed for modification — is what the factory buys you. It's the same reason PROVIDER_REGISTRY exists rather than a giant match on provider names.

2. The Output factory design

Mirrors the Provider/Model/Capability pattern exactly. One call to define_factory!, one static registry, implementations registered at startup.

// src/utils/ui/output.rs

use crate::registry::ConfigConstructable;
use crate::define_factory;

/*-- public --*/

/// The core output abstraction. Commands call these methods;
/// they never know which backend is rendering.
pub trait Output: ConfigConstructable + Send + Sync {
    /// Render a tabular result (catalog, list, health)
    fn table(&self, title: &str, headers: &[&str], rows: &[Vec<String>]);

    /// Render a key-value detail block (info commands)
    fn detail(&self, title: &str, fields: &[(&str, String)]);

    /// Render a status row with ok/fail colouring
    fn status(&self, label: &str, ok: bool, detail: &str);

    /// Plain informational message
    fn info(&self, msg: &str);

    /// Warning message
    fn warn(&self, msg: &str);

    /// Error message (goes to stderr in terminal mode)
    fn error(&self, msg: &str);
}

/// Metadata for a registered output backend
#[derive(Debug, Clone)]
pub struct OutputMetadata {
    pub name: String,
    pub description: String,
}

// Generate OutputFactory, HasOutputMetadata, etc.
define_factory!(Output, OutputMetadata, OutputFactory);


// src/utils/ui/mod.rs

pub static OUTPUT_REGISTRY: LazyLock<OutputFactory> = LazyLock::new(|| {
    let mut f = OutputFactory::new();
    f.register::<TerminalOutput>("terminal");   // coloured ratatui one-shot
    f.register::<JsonOutput>("json");            // --output=json for scripts
    f.register::<PlainOutput>("plain");          // no ANSI, for pipes/CI
    // TuiOutput is NOT in the registry — it owns a live event loop,
    // it's constructed directly in the None arm of main()
    f
});
The interactive TUI (app.rs) is not registered in the factory because it doesn't take a one-shot config and return — it runs an event loop and exits. That's a different lifecycle. It's constructed directly in main()'s None arm. Everything else goes through the registry.

Selecting the output format from the CLI

// Add a global flag to Cli in main.rs:
#[derive(Parser)]
struct Cli {
    /// Output format (terminal, json, plain)
    #[arg(long, global = true, default_value = "terminal")]
    output: String,

    #[command(subcommand)]
    command: Option<Commands>,
}

// In main():
Some(cmd) => {
    let out = OUTPUT_REGISTRY
        .construct(&cli.output, &serde_json::json!({}))
        .unwrap_or_else(|_| {
            eprintln!("Unknown output format: {}", cli.output);
            std::process::exit(1);
        });
    dispatch_command(&mut ctx, cmd, out.as_ref()).await
}

Now granite-cli model catalog --output json just works. The command layer is completely unchanged.

3. How decoupled is this really — the full dependency map

Here's every layer and what it knows about:

LayerKnows aboutDoes NOT know about
src/commands/*.rs &dyn Output, domain data (ModelMetadata etc.), AppContext ratatui, crossterm, JSON serialisation, terminal setup, TUI state
src/utils/ui/output.rs (trait) Domain data shapes (what a row looks like) Commands, registries, config, ratatui internals
TerminalOutput impl ratatui widgets, crossterm Commands, app state, domain logic
JsonOutput impl serde_json ratatui, terminal, commands
src/utils/ui/app.rs (TUI) ratatui, AppContext, same widget code as TerminalOutput Command structs (it calls registries directly)
OutputFactory define_factory! infrastructure Every concrete impl — it only stores Box<dyn OutputMetadata_>

The result: you can delete any output backend and nothing else breaks. You can add a new backend without touching commands or main. Commands can be unit-tested in complete isolation using a test double that captures output into a Vec<String> — no terminal needed.

4. Adding a new output format — what it actually looks like

Say someone asks for --output markdown six months from now. Here's the complete list of files you touch:

  1. Create src/utils/ui/backends/markdown.rs
  2. Add one line to src/utils/ui/mod.rs: f.register::<MarkdownOutput>("markdown");
  3. That's it. No changes to any command, no changes to main.rs, no changes to the trait definition.
// src/utils/ui/backends/markdown.rs  (the entire new file)

pub struct MarkdownOutput;

impl ConfigConstructable for MarkdownOutput {
    fn new(_cfg: &serde_json::Value) -> Self { Self }
}

impl Output for MarkdownOutput {
    fn table(&self, title: &str, headers: &[&str], rows: &[Vec<String>]) {
        println!("## {}", title);
        println!("| {} |", headers.join(" | "));
        println!("| {} |", headers.iter().map(|_| "---").collect::<Vec<_>>().join(" | "));
        for row in rows {
            println!("| {} |", row.join(" | "));
        }
    }
    fn detail(&self, title: &str, fields: &[(&str, String)]) {
        println!("## {}", title);
        for (k, v) in fields { println!("- **{}**: {}", k, v); }
    }
    fn info(&self, msg: &str)  { println!("{}", msg); }
    fn warn(&self, msg: &str)  { println!("> ⚠️ {}", msg); }
    fn error(&self, msg: &str) { eprintln!("> ❌ {}", msg); }
    fn status(&self, label: &str, ok: bool, detail: &str) {
        println!("- {} {}: {}", if ok { "✅" } else { "❌" }, label, detail);
    }
}

impl HasOutputMetadata for MarkdownOutput {
    fn metadata() -> OutputMetadata {
        OutputMetadata {
            name: "markdown".to_string(),
            description: "Markdown-formatted output".to_string(),
        }
    }
}

5. Test strategy — layers and what to test at each

The existing codebase has three test patterns you should follow exactly:

PatternWhere it appearsWhat it tests
Pure unit tests on private helpers schema_prompt.rs — tests is_secret_schema, resolve_ref, zero_value_for Logic that doesn't touch I/O at all. No terminal, no network. Fast.
Factory mechanic tests with test doubles registry/mod.rs — defines TestImpl1/2 inline, tests register/construct/entries The macro-generated infrastructure works correctly for any trait.
Integration tests with real registry + fake config providers/mod.rs — builds a real Config, runs ProviderSource::from_config The wiring between config, registry, and construction is correct end-to-end.

The new Output system introduces a fourth pattern that doesn't exist yet:

New patternWhat it enables
Spy/capture output in command tests A CaptureOutput test double that records every call. Commands can be tested without a terminal by asserting on the captured calls.

This is the most important new testing capability — today you cannot test any command behaviour without it actually printing to a real terminal. The Output abstraction fixes that.

#[cfg(test)]
mod tests {
    use super::*;

    // ── CaptureOutput (the test double, defined once, used everywhere) ──

    /// Records every Output call as a structured event.
    /// Used in all command-layer tests.
    #[derive(Default)]
    pub struct CaptureOutput {
        pub tables:  Vec<(String, Vec<String>, Vec<Vec<String>>)>, // title, headers, rows
        pub details: Vec<(String, Vec<(String, String)>)>,           // title, fields
        pub infos:   Vec<String>,
        pub warns:   Vec<String>,
        pub errors:  Vec<String>,
        pub statuses: Vec<(String, bool, String)>,                    // label, ok, detail
    }

    impl ConfigConstructable for CaptureOutput {
        fn new(_cfg: &serde_json::Value) -> Self { Self::default() }
    }

    impl Output for CaptureOutput {
        fn table(&self, title: &str, headers: &[&str], rows: &[Vec<String>]) { /* append */ }
        fn detail(&self, title: &str, fields: &[(&str, String)]) { /* append */ }
        fn info(&self, msg: &str)  { self.infos.push(msg.to_string()); }
        fn warn(&self, msg: &str)  { self.warns.push(msg.to_string()); }
        fn error(&self, msg: &str) { self.errors.push(msg.to_string()); }
        fn status(&self, label: &str, ok: bool, detail: &str) { /* append */ }
    }

    // Note: CaptureOutput uses interior mutability (RefCell) for the Vecs
    // since Output methods take &self not &mut self. See full impl below.

    // ── Output factory tests ──────────────────────────────────────────

    #[test]
    fn output_registry_has_terminal_and_json_backends() {
        assert!(OUTPUT_REGISTRY.get("terminal").is_some());
        assert!(OUTPUT_REGISTRY.get("json").is_some());
        assert!(OUTPUT_REGISTRY.get("plain").is_some());
    }

    #[test]
    fn output_registry_construct_unknown_errors() {
        let result = OUTPUT_REGISTRY.construct("nonexistent", &serde_json::json!({}));
        assert!(result.is_err());
    }

    #[test]
    fn output_registry_entries_lists_all_backends() {
        let entries = OUTPUT_REGISTRY.entries();
        assert!(entries.len() >= 3);
        assert!(entries.contains_key("terminal"));
        assert!(entries.contains_key("json"));
    }

    #[test]
    fn output_metadata_has_name_and_description() {
        let meta = OUTPUT_REGISTRY.get("terminal").unwrap();
        assert!(!meta.name.is_empty());
        assert!(!meta.description.is_empty());
    }
}

Command layer tests — using CaptureOutput
src/commands/model.rs #[cfg(test)]

This is the big win. Commands that previously had no testable output now have fully assertable behaviour.

#[cfg(test)]
mod tests {
    use super::*;
    use crate::config::Config;
    use crate::AppContext;
    use crate::utils::ui::output::CaptureOutput;

    fn empty_ctx() -> AppContext {
        AppContext { config: Config::default() }
    }

    // ── catalog ───────────────────────────────────────────────────────

    #[test]
    fn catalog_renders_a_table_with_id_family_size_context_type_columns() {
        let ctx = empty_ctx();
        let out = CaptureOutput::default();
        ModelCommands::catalog(&ctx, None, &out).unwrap();

        assert_eq!(out.tables.len(), 1);
        let (_, headers, _) = &out.tables[0];
        assert!(headers.contains(&"ID".to_string()));
        assert!(headers.contains(&"FAMILY".to_string()));
        assert!(headers.contains(&"TYPE".to_string()));
    }

    #[test]
    fn catalog_with_no_filter_returns_all_models() {
        let ctx = empty_ctx();
        let out = CaptureOutput::default();
        ModelCommands::catalog(&ctx, None, &out).unwrap();

        let (_, _, rows) = &out.tables[0];
        assert!(!rows.is_empty(), "Should have at least one model");
    }

    #[test]
    fn catalog_filtered_by_text_only_shows_text_models() {
        let ctx = empty_ctx();
        let out = CaptureOutput::default();
        ModelCommands::catalog(&ctx, Some(ModelType::Text), &out).unwrap();

        let (_, _, rows) = &out.tables[0];
        for row in rows {
            // TYPE column is index 4
            assert_eq!(row[4], "Text", "All rows should be Text type");
        }
    }

    #[test]
    fn catalog_filtered_by_vision_excludes_text_models() {
        let ctx = empty_ctx();
        let out = CaptureOutput::default();
        ModelCommands::catalog(&ctx, Some(ModelType::Vision), &out).unwrap();
        let (_, _, rows) = &out.tables[0];
        assert!(rows.iter().all(|r| r[4] == "Vision"));
    }

    #[test]
    fn catalog_empty_filter_result_emits_info_not_table() {
        // Embedding type has 0 models currently → should emit info, not an empty table
        let ctx = empty_ctx();
        let out = CaptureOutput::default();
        ModelCommands::catalog(&ctx, Some(ModelType::Embedding), &out).unwrap();
        assert_eq!(out.tables.len(), 0);
        assert!(!out.infos.is_empty(), "Should print a 'no models found' message");
    }

    // ── list ──────────────────────────────────────────────────────────

    #[test]
    fn list_with_empty_config_renders_empty_table() {
        let ctx = empty_ctx();
        let out = CaptureOutput::default();
        ModelCommands::list(&ctx, None, &out).unwrap();
        let (_, _, rows) = &out.tables[0];
        assert_eq!(rows.len(), 0);
    }

    #[test]
    fn list_shows_configured_model_with_provider() {
        let mut ctx = empty_ctx();
        ctx.config.models.insert("granite-3.1-8b-instruct".to_string(),
            crate::config::ModelConfig {
                provider_id: Some("my-ollama".to_string()),
                enabled: true, variant: None,
            }
        );
        let out = CaptureOutput::default();
        ModelCommands::list(&ctx, None, &out).unwrap();
        let (_, _, rows) = &out.tables[0];
        assert_eq!(rows.len(), 1);
        assert!(rows[0].iter().any(|c| c == "my-ollama"));
    }

    // ── info ──────────────────────────────────────────────────────────

    #[test]
    fn info_known_model_renders_detail_block() {
        let ctx = empty_ctx();
        let out = CaptureOutput::default();
        ModelCommands::info(&ctx, "granite-3.1-8b-instruct", &out).unwrap();
        assert_eq!(out.details.len(), 1);
        let (title, fields) = &out.details[0];
        assert!(title.contains("granite-3.1-8b-instruct"));
        assert!(fields.iter().any(|(k, _)| *k == "Family"));
        assert!(fields.iter().any(|(k, _)| *k == "Context Length"));
    }

    #[test]
    fn info_unknown_model_returns_error() {
        let ctx = empty_ctx();
        let out = CaptureOutput::default();
        let result = ModelCommands::info(&ctx, "does-not-exist", &out);
        assert!(result.is_err());
    }
}

src/utils/ui/output.rs #[cfg(test)]

Your test double needs its own tests — otherwise a bug in the spy silently invalidates all the command tests.

#[test]
fn capture_output_records_table_calls() {
    let out = CaptureOutput::default();
    out.table("My Table", &["A", "B"], &[
        vec!["row1a".to_string(), "row1b".to_string()],
    ]);
    assert_eq!(out.tables.len(), 1);
    let (title, headers, rows) = &out.tables[0];
    assert_eq!(title, "My Table");
    assert_eq!(headers, &["A".to_string(), "B".to_string()]);
    assert_eq!(rows[0], vec!["row1a", "row1b"]);
}

#[test]
fn capture_output_records_multiple_tables_independently() {
    let out = CaptureOutput::default();

Output backend contract tests
src/utils/ui/backends/*.rs #[cfg(test)]

Every backend implementation should pass the same contract tests — "given these inputs, does it produce valid output without panicking?" These don't assert on formatting aesthetics, just that the backend handles edge cases correctly.

// A macro that generates the same contract tests for any Output impl.
// Run it in each backend's own test module.

macro_rules! output_contract_tests {
    ($backend:expr) => {
        #[test]
        fn empty_table_does_not_panic() {
            let out = $backend;
            out.table("Empty", &["A", "B"], &[]);
            // must not panic
        }

        #[test]
        fn table_with_many_rows_does_not_panic() {
            let out = $backend;
            let rows: Vec<Vec<String>> = (0..100)
                .map(|i| vec![format!("id-{}", i), format!("val-{}", i)])
                .collect();
            out.table("Big Table", &["ID", "VAL"], &rows);
        }

        #[test]
        fn table_row_with_empty_strings_does_not_panic() {
            let out = $backend;
            out.table("T", &["A"], &[vec!["".to_string()]]);
        }

        #[test]
        fn detail_with_no_fields_does_not_panic() {
            let out = $backend;
            out.detail("Empty Detail", &[]);
        }

        #[test]
        fn status_ok_and_fail_do_not_panic() {
            let out = $backend;
            out.status("svc", true, "");
            out.status("svc", false, "timed out");
        }

        #[test]
        fn info_warn_error_with_empty_string_do_not_panic() {
            let out = $backend;
            out.info("");
            out.warn("");
            out.error("");
        }
    };
}
